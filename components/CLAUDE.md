# components/

## Base UI, not Radix

These shadcn components are built on **`@base-ui/react`** (`components.json` style is `base-nova`), not Radix. Radix import paths, prop names, and composition patterns do **not** transfer — most training-data shadcn examples assume Radix and will be wrong here. Read a neighbouring component in `ui/` before writing a new one.

Roughly two-thirds of `ui/` are client components; the rest are server-safe. Check for `"use client"` before assuming either way.

## Conventions in ui/

- **`cn` is imported from the bare `cn` package** — `import { cn } from "cn"` — not from `@/lib/utils`. `lib/utils.ts` is only a re-export shim. Every component does it this way; match them.
- Variants use `class-variance-authority`; icons are `lucide-react`.
- These files are shadcn-generated and **omit semicolons**. Match the file you are editing rather than the `app/` style.
- Path aliases come from `components.json`: `@/components`, `@/components/ui`, `@/lib`, `@/hooks`.

Files in `ui/` are generated by the shadcn CLI and may be overwritten when a component is re-added. Prefer wrapping them in a new component over editing them in place; if an edit is unavoidable, keep it small and obvious.

## kiosk/

The Beacon Box screens. Hand-written, so unlike `ui/` they **use semicolons and double quotes** — match `app/` and `lib/`, not the shadcn-generated files next door.

`kiosk-shell.tsx` is the only `"use client"` entry that matters; everything else is pulled into the client graph through it.

Three conventions hold across every screen here:

- **Size in `cqw`, not rem.** Each screen is its own `@container` and sizes type, gaps, and controls in `cqw` (`text-[2.4cqw]`, `size-[9cqw]`). That is what lets one layout serve 1080x1920, 720x1280, and a letterboxed dev window with no breakpoints. Shadcn's own scale is rem-based and built for a laptop — `ui/button.tsx` tops out at `h-9` (36 px), which is unusable at kiosk distance.
- **No `max-w-*` on a screen.** The shell already locks the panel to 9:16; a width cap gutters it on tall viewports.
- **Tenant colour comes from `--brand`, not `--primary`.** `brandStyle()` in `lib/tenants.ts` sets `--brand`, `--brand-foreground`, `--brand-muted` (and aliases `--primary`/`--ring`) via an inline style on a wrapper. Use `bg-brand` / `text-brand-foreground` for anything that should wear the tenant's identity.

`className` overrides beat a shadcn `cva` variant, because `cn` is a real tailwind-merge drop-in — so `<Button className="h-28 text-4xl">` works and you never need to edit `ui/`.

### Two traps already paid for

**`ui/input-otp.tsx` is the wrong base for the PIN pad.** It wraps the `input-otp` package's `OTPInput`, a real focusable text input with caret state that expects typing — on a touchscreen, focusing it raises the OS keyboard, and its slots only render active while focused. The readout is plain divs for that reason.

**`ring-dashed` does not exist.** Rings are box-shadows and cannot dash; it renders a solid outline. Use `border-2 border-dashed`.

## Theme

Tailwind v4 is CSS-first — there is no `tailwind.config.*`. It all lives in `app/globals.css`: raw tokens in `:root` / `.dark`, and `@theme inline` mapping them onto utility namespaces. Dark mode is the class variant `@custom-variant dark (&:is(.dark *))`, so dark styles need a `.dark` ancestor — **nothing in the app sets one**, by choice. The `.dark` block is dead code kept for a future toggle; `dark:` utilities inside `ui/` simply never fire.

`--radius-sm` through `--radius-4xl` are multiples of `--radius`, so one edit rescales the whole set.

`--brand`, `--brand-foreground` and `--brand-muted` are tenant tokens with neutral Beacon Box defaults. They are overridden at runtime by an inline style, and **that only works because the mapping is `@theme inline`** — with `inline`, `bg-brand` compiles to a live `var(--brand)` rather than a baked literal. Drop the word `inline` and per-tenant theming stops working silently, with no error.

`--animate-shake` plus a top-level `@keyframes shake` drive the wrong-PIN feedback; `tw-animate-css` ships no shake. React will not restart a CSS animation just because the same class is re-added, so the keypad remounts the readout with a `key` on each failure.

The palette is a [tweakcn](https://tweakcn.com) export (pink primary, teal accent) that was **merged into** the file rather than pasted over it. Pasting a fresh export wholesale is the obvious move and it quietly breaks things: an export carries no `@import` lines, so it drops `tw-animate-css` and `shadcn/tailwind.css`, and its radius scale stops at `xl` while `rounded-2xl` and `rounded-4xl` are in use here. Merge new tokens into the existing `:root` / `.dark` blocks and leave the structure around them alone.

Two quirks of that export, so you don't debug them as merge errors:

- `--muted-foreground` shipped identical to `--foreground` in light mode, which made `text-muted-foreground` de-emphasise nothing. **Fixed** — `:root` now carries a real value at 4.62:1 on `--background` (WCAG AA for body text). The app runs light, so don't paste that token back from an export.
- `--shadow-x`, `--shadow-y`, `--shadow-blur`, `--shadow-spread`, `--shadow-opacity`, `--shadow-color` are tweakcn's editor metadata. The `--shadow-*` sizes are literal values, not derived from them, so editing these changes nothing.

## Fonts

`--font-sans` and `--font-mono` resolve to `var(--font-outfit)` and `var(--font-fira-code)`, which `app/layout.tsx` supplies via `next/font/google`. Swapping a font is therefore two files — the `next/font` call and the `:root` token.

Naming a family directly in the token instead (`--font-sans: Outfit, sans-serif`, which is how tweakcn exports it) compiles clean and silently renders a system fallback, because nothing ever loads the file.
